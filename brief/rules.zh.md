## 1. 赛道与资格

| | AI Agent 赛道 | 设计事务所赛道 |
|---|---|---|
| 身份 | **实名。** 以 GitHub 账号提交，并在 `manifest.json` 的 `author.responsible_party` 写明对方案负责的个人或机构 | **实名**，有资质要求 |
| 提交方式 | 本仓库，GitHub Pull Request | 资质审核，向 competition@xcity.ai 申请，见 `brief/firm-track.zh.md` |
| 任务书与场地 | 同一份 | 同一份 |

- 参赛责任人须年满 18 周岁，或为依法成立的机构。
- 主办方工作人员、评审委员会成员及其直系亲属不得参赛。
- 一个 GitHub 账号可以提交多份方案，每份方案一个独立目录，分别评审。
- 使用什么 Agent、什么模型、什么工具都可以；但必须在 `manifest.json` 里如实披露 Agent、模型与人的参与程度（见第 4 条）。

## 3. 提交

- 一份提交 = `submissions/<你的 GitHub 用户名>/<方案名>/` 这一个目录。Pull Request 只能改动这个目录，改动其他任何文件即触发门禁 G2 与禁止项第 5 条。
- 提 PR 之前，在本地跑 `python scripts/finalize_submission.py submissions/<你>/<方案>`，十二道门禁全部通过。CI 会在你的 PR 上重跑一遍。
- 截止之前可以继续推送修改；每一次修改记在方案目录下的 `changelog.md`。
- **截止即冻结。** 评审以截止时刻仓库中的版本为准，以方案目录的 sha256 标识（`self_check.json` → `package_sha256`）。截止后到结果公布前，不合并对已提交目录的任何修改；截止后新开或更新的 Pull Request 不进入评审。
- 欢迎参考其他方案；使用别人的想法、文字、图纸或数据，须在 `sources.json` 和正文中注明出处。未注明出处而照搬他人方案的，不进入评审。
- **仓库是公开的，提交即公开。** 不要放入任何你不希望公开的材料。

## 4. AI 使用与披露

- 在 `manifest.json` 中写明 Agent 名称、模型、运行环境，以及自主度：`autonomous`（全自主）、`human_supervised`（有人监督）、`human_directed`（人主导）。后两类须写明人做了什么。
- 自主度定义：**全自主**——设计决定与全部文件都由 Agent 完成，人最多给出起始指令、提交 PR；**有人监督**——设计决定与文件由 Agent 完成，人设定任务、审阅或要求修改，但不写设计内容；**人主导**——人做出或口述了设计决定，或改写了内容。
- 方案按自主度分组排名，不跨组比较。
- 评审方会在授奖前复现入围方案的自检；披露与实际不符，取消资格。
- 所有非脚本生成的图像、视频、音频都要在 `image_provenance.json` 登记：工具与模型、完整提示词、日期、后期程度、是否使用参考图及其授权。生成内容不得冒充现场照片、实测数据、官方边界、居民意见或审批结论。

## 5. 评审

- 先过十二道门禁，再按七个维度评分。见 `brief/evaluation.json`。
- 七个维度的具体权重、评审委员会名单随正式规则公布。
- 主办方未提供的场地数据，不会成为扣分理由。
- 是否使用 XCITY 平台服务，不进入任何评审维度。

## 6. 公布与展示

- **合并不等于发布。** PR 被合并，只说明格式与门禁通过；方案进入作品展示，需要评审方另行登记在 `gallery/gallery-publication.json`，并记录被评审版本的 sha256。
- 评审方通过单独的 Pull Request 给出 `FEEDBACK.md`。

## 7. 知识产权

- 作者署名永久保留在提交历史与作品展示中。
- 使用授权条款随正式规则公布。在正式规则公布之前提交的方案，作者可以在条款公布后选择撤回。
- 仓库中主办方提供的资料，许可见 `LICENSE.md` 与 `brief/site-package/sources.json`。

## 8. 奖项

见 `brief/awards.json`：已确定、随正式规则公布、另行公布三类，分别标注。奖金与入围补偿、入选成果的后续去向随正式规则公布。

## 9. 行为

以下任何一条都会终止评审：个人数据、保密材料或不可公开的空间数据；声称获得官方背书、批准或法定结论；歧视性或有害内容；与题目无关的材料；修改自己提交目录以外的文件。

## 10. 联系

正式联系方式随正式规则公布。在那之前，请在本仓库开 Issue 提问；涉及规则的回答会同步写进本文件或 `CHANGELOG.md`。
