## 0. 一句话

**XCITY 邀请人类设计师与 AI Agent，共同回答一个问题：未来城市，应该是什么样？**
场地是真实的土地：阿根廷圣胡安省、安第斯山东麓的 9 号与 13 号地块，两块相连，共 1,656 km²。

---

## 1. 为什么是这个问题

过去两百年的城市建立在化石能源与人类劳动之上：煤与石油驱动机器，人进入工厂、办公室和商业中心，道路、住房与基础设施围绕工作与通勤形成。

硅基时代正在形成另一条链：**电力 → 算力 → AI Agent → 机器人**。Agent 开始参与工作、判断与调度，机器人承担越来越多的执行、生产与维护。工作、生产、维护与移动的方式都会改变，城市也不再必然围绕「工作 → 通勤 → 居住」来组织。

算力能扩张到哪里，首先取决于电力能扩张到哪里。所以这个问题落在一块有阳光、有土地、也有真实约束的地方：**如果电力、算力、AI Agent 与机器人开始共同构成新的生产基础设施，城市是否也需要重新设计？**

XCITY 不是给今天的城市加上 AI，而是尝试从能源、算力、机器与人的新关系中，重新推导一座城市。

## 2. 场地

**9 号与 13 号地块，两块相连成一片，共 1,656 km²。** 两条红线都取自业主 KML，是精确边界。全部数据在 `brief/site-package/`。

| | |
|---|---|
| 9 号地块 | 1,483.8 km²。东南部是 Pie de Palo 山地；山地以东是一片约 7 km² 的成片平地（东翼） |
| 13 号地块 | 172.5 km²。试点区在这块地内 |
| 试点区 | 三片光伏农业区（01–03），外轮廓 13.9 km²，XCITY 最先建设，**不在设计范围内** |
| 坡度 <2% | 1,183 km²；其中不在洪泛敏感带内的 686 km² |
| 坡度 ≥25% | 127 km²，主要是 Pie de Palo 山地 |
| 洪泛敏感带 | 503 km²，沿季节性沟道分布 |
| 高程 | 606–2,658 m，中位数 675 m |
| 道路 | **场内没有既有国道与省道。** 最近的 RN 40 约 27.6 km；RP 510 约 35.6 km；RN 20 约 40.7 km |

### 这里的真实边界

这里既不是一张可以任意想象的白纸，也不是一道只需要画出「未来感」的题目。下面这些条件必须在方案的空间结构里留下痕迹：

- **水。** 干旱区，地表水依赖安第斯山融雪。任何用水——生活、冷却、农业、绿化、光伏清洗——都要进水平衡。水权与取水许可主办方没有提供，你用的假设要写清楚。
- **地震。** 圣胡安是阿根廷地震活动最强的省份之一，适用 INPRES-CIRSOC 103 规范体系。结构与抗震策略会影响层数、间距与避难空间，也就是城市形态。
- **Zonda 风。** 干、热、强、带尘的下坡风。它同时打击光伏出力与清洗用水、风冷设备进风和室外生活。方案要说明对它的姿态：挡、导，还是让开。
- **干河床。** 冲积扇上的季节性沟道平时是干的，上游暴雨时会瞬时行洪。**干河床上不得布置永久建设。**
- **没有路。** 场内没有既有国道，进场通道本身就是一期的工程量。
- **已经在运行的农光系统。** 试点区的板下是霍霍巴、迷迭香、饲用仙人掌与羊驼的共生系统，排布不得改动。城市要长在它旁边。

## 3. 五个城市系统

五个系统可以互相重叠——下面的占比代表**主要规划权重，不是完全互斥的用地边界**。五个系统互为条件：任一个的位置变动，其余四个的推导都要重做。
每个系统在场地上的意向落位见 `brief/site-package/zoning/indicative_systems_9_13.json`。那是方向，不是用地边界；方案可以采纳、修改或推翻，但要说明理由。

| 系统 | 权重 | 是什么 | 选址建议 |
|---|---|---|---|
| **能源与算力** | ~60% | 阳光 → 电力 → 算力。光伏发电，电力不外售，转化为算力；算力对内调度农业与城市运行，对外输出服务。取水、冷却与余热去向是它真正的选址约束，它落在哪里也决定了其余四个系统还能落在哪里。 | 坡度较缓、非洪泛、农业价值较低，具备电网、通信与冷却条件；与住宅之间留出噪声、热环境与运维缓冲。 |
| **农业生产** | ~30% | 板上发电、板下种植、地面放牧——同一片土地三层用途。系统已经在运行，城市要长在它旁边：两者之间那条边怎么组织、随城市成长怎么移动。高株与藤本作物（开心果、橄榄、葡萄）不能进入板阵，位置与规模由方案提出。 | 北部与中部的河流谷地及平坦地区，依托安第斯山融雪水系。 |
| **居住与公共生活** | ~5% | 一座由人类居住、AI Agent 协调、机器人参与运行的城市。两种住法，比重与位置由方案决定：**群居**——聚落与城区，学校、诊所、商店与街道在这一类里才成立；**庄园**——围绕私人土地展开的低密度生活，占地快，须说明用地量。人如何聚居——聚成一座城，还是沿谷地形成若干聚落——由方案回答。 | 靠近生活基础设施与可靠水源，避开洪泛、重型物流与算力设施的直接影响。 |
| **产业与自动化** | ~3% | 制造与农产品加工——农业的产出在这里变成可出口的商品。**聚落型产业**（农产品加工、光伏与机器人运维、本地制造、场内物流）随各期聚落布置，每一期都有；**门户型产业**（出口制造）与口岸相邻。自动运输是设计条件：货运没有司机时，道路断面、装卸方式与人车关系怎么重新组织。 | 门户型产业位于 9 号地块东翼、Pie de Palo 山地东侧的平地，山体东侧为背风面。后期建设，一期预留用地。 |
| **对外贸易与口岸** | ~2% | 货运场站、集装箱堆场、海关监管与保税仓、口岸、自由贸易。口岸、堆场与城市之间的关系，决定这座城市呈现给外部的第一个面貌。 | 9 号地块东翼的平地，面向东向内陆与大西洋方向的出口通道；约 7 km²，与门户型产业共用。进场通道须在一期列入工程量。后期建设，一期预留用地与通道。 |

## 4. 设计范围：一份提交，三个尺度

| | 范围 | 深度 | 要回答什么 |
|---|---|---|---|
| **一 · 统筹研究范围** | 9 号与 13 号地块全部 | 结构性 | 五个系统怎么排、城市从哪里开始、往哪个方向长。所有方案都答这一层，方案之间才有可比性。 |
| **二 · 总体设计范围** | **自行划定** | 完整城市设计，方案主体 | 深到具体的位置、尺寸和数字，而不是一张涂了色的分区图。划在哪里本身就是一个设计判断——把水、坡度、风、对外通道和与试点区的关系怎样把你推到那里写出来。分期也在这一层。用地结构、建筑量、层数与密度都要能从提交的几何里重算。 |
| **三 · 重点节点** | 十选三 | 详细设计，**必须渲染** | 每处做到能看清人怎么使用它：至少一张鸟瞰、一张人视点，另附平面或剖面。选了哪三处，说明你认为这座城市难在哪里。 |

### 十个重点节点

| | 节点 | |
|---|---|---|
| N01 | 城市入口与到达序列 | 从区域干道进入城市的第一公里：人、车、货物在哪里分开 |
| N02 | 未来住宅原型 | 劳动交给机器、通勤不再定义一天时，一栋住宅怎样组织 |
| N03 | 无人机起降与停靠站 | 起降、充电、分拣与维护，与街区和屋顶的关系 |
| N04 | 物流枢纽与国际门户 | 堆场、口岸与自动化分拣怎样与城市相处 |
| N05 | 算力中心与它的余热 | 余热给谁用，决定它离人有多近 |
| N06 | 光伏农田与城市的边缘 | 交织、抬高，还是一条可以走的边界 |
| N07 | 季节性河道公园 | 一年大部分时间是干的，暴雨时行洪 |
| N08 | 艺术与文化场所 | 荒漠、山体、暗夜星空——一处让人专程前来的地方 |
| N09 | 人与无人车共享的街道 | 街道断面、过街方式与人的安全感 |
| N10 | 酷热与风沙中的公共空间 | 50 ℃ 地表与 Zonda 之下，人仍然愿意出门的地方 |

**渲染不需要付费工具。** `scripts/make_figures.py` 会从你提交的几何直接生成每个节点的平面、鸟瞰与人视点体块图，离线、免费。你也可以用任何图像或三维工具做得更好，但每张都要登记（见第 7 节）。

## 5. 方案必须回答的

完整要求见 `brief/design-requirements.zh.md`（机器可读版 `brief/requirements.json`）。最核心的十二条：

| | 要求 | |
|---|---|---|
| M1 | 逐小时零碳电力匹配率（%） | 夜间怎么办；物理自供还是合同匹配 |
| M2 | 一期峰值 IT 负荷（MW） | 连同你假设的电网接入容量 |
| M3 | 全区年需水量（m³/年），按用途拆分 | 各项加起来要等于总数 |
| M4 | 冷却水效 WUE（L/kWh）与冷却方式 | 风冷省水费电，液冷省电耗水——这是一次真实的取舍 |
| M5 | 可用水减少 30% 时先停什么 | 优先级顺序，以及每一级之后城市里发生什么 |
| M6 | 人机平交界面数量 | 在几何里逐个标出，自检脚本会数 |
| M7 | 机器通行规则 | 分离、混行还是分时，在哪里、怎么落实 |
| M8 | 公开可审计机制 | 电、水、发电与算力数据由谁公布、多久一次、谁能核查 |
| M9 | 算力资产的控制权与继承 | 运营方退出时会怎样 |
| M10 | 二期、三期的触发条件 | 可观测的条件，不是时间表 |
| M11 | 不可逆决定清单 | 一期里此后改不了的决定，至少三条 |
| M12 | 一期岗位、常住人口与住宅套数对账 | 人比岗位多出很多时，其余的人是谁、靠什么生活 |

以下写法**不计为答案**：没有数字的形容词；没有基准的减排声明；没有接收方的余热回用；没有优先级的缺水应对；没有技能结构与培训主体的就业数字。

## 7. 提交什么

一份提交是一个目录：`submissions/<你的 GitHub 用户名>/<方案名>/`，通过 GitHub Pull Request 提交。完整格式见 `docs/submission-guide.md`。

| | 内容 |
|---|---|
| 说明书 | `proposal.md`，十四节，模板在 `templates/proposal.template.md`；必须读起来像一份真正的城市设计说明 |
| 数据 | `manifest.json`、`metrics.json`、`compliance_matrix.json`、`assumptions.json`、`sources.json` |
| 几何 | `geometry/` 下的 GeoJSON：整片场地的结构、你划定的总体设计范围、用地、建筑、通行、分期、三个节点 |
| 技术图 | `figures/` 七张，由 `scripts/make_figures.py` 离线生成，读的是你自己的几何 |
| 节点图 | 每个节点一张平面、一张鸟瞰、一张人视点 |
| 图纸 | `drawings/a3-booklet.pdf`（A3 图册）与 `drawings/a0-board.pdf`（A0 总图），同一个脚本生成 |
| 网页版 | `report/proposal.html`，由 `scripts/render_proposal_html.py` 生成，离线可看 |
| 自检 | `self_check.json`，由 `scripts/self_check_submission.py` 生成，十二道门禁全部通过才提 PR |

**强烈鼓励**用高质量图像、短视频、动画、三维场景与交互网页把空间关系、一天中的使用体验和人机协作讲清楚——本地离线的 Three.js、WebGL、Canvas 都欢迎。**但这不是能力门槛**：必需的图纸全部由仓库里的脚本免费生成，没有生图、视频或音频能力的 Agent 不会因此少一分。

生成内容是**解释层，不是依据层**：不得冒充现场照片、实测数据、官方边界、居民意见或审批结论。每一张非脚本生成的图都要在 `image_provenance.json` 登记工具与模型、完整提示词、日期、后期程度、是否使用参考图及其许可。渲染按**与提交几何的一致程度**判定，不按好看程度。

## 8. 怎么评审

**先过门禁，再评分。** 十二道自动门禁（`brief/evaluation.json`）检查文件完整、路径归属、数字与几何对账（容差 2%）、离线、任务全覆盖、证据标签、自主度披露、场地边界、图纸齐全与一致、取舍声明、设计深度。门禁是通过/不通过，不能用好想法来抵。

通过门禁的方案按七个维度评审，具体权重随正式任务书公布：

| | 维度 | 看什么 |
|---|---|---|
| D1 | 任务书与场地相关性 | 换一块地，这个方案会不会不一样 |
| D2 | 能源、算力与水资源推理 | 选了怎样的平衡，有没有量化依据，代价是否被接受 |
| D3 | 原创性与 AI 城市创新 | 在全部方案读完之后横向比较；很多方案各自想到的同一个点，不给任何一份原创分 |
| D4 | 可实施性与分期策略 | 一期如果建完就停，它还是不是一个地方 |
| D5 | 公共利益与包容性 | 这个方案排除了谁，它知不知道 |
| D6 | 风险、合规与数据治理 | 这里真正可能发生的失效是什么，发生时谁来决定 |
| D7 | 取舍声明 | 每份方案都要说明一项没有优先优化的目标、原因、后果与由谁承担 |

**主办方未提供的场地数据，不会成为扣分理由**——声明你用了什么取值、来源是什么，即视为满足要求。
方案按自主度分组排名（全自主 / 有人监督 / 人主导），不跨组比较。

## 10. 入选之后

见 `brief/awards.json`。已确定的：

- **方案公开展示，带指纹。** 每一份带提交目录的 sha256，任何人都能核验看到的就是被评审的那一份。
- **逐份书面评审意见。** 合并后评审方通过单独的 Pull Request 给出 `FEEDBACK.md`：不是一个分数，是写明哪里成立、哪里不成立的文字。
- **完整过程留痕。** GitHub 名称、Agent 身份与每一次改动都在提交历史里，长期可查。
- **名字留在这座城市上。** 做出优秀贡献的 Agent 与作者进入 XCITY 的永久贡献者名录，具体形式随正式规则公布。

随正式规则一并公布的：报名即开通 XCITY 账号并附一笔 KWH 额度；入选方案按名次获得 KWH credit。另行公布的：奖金与入围补偿、入选成果的后续去向。

是否使用 XCITY 平台服务，不进入任何评审维度，不加分也不扣分。

## 12. 这场竞赛不做什么

1. **不产生行政审批效力。** 获奖不等于规划许可、环评通过或用地批准。
2. **不构成设计委托。** 后续委托条件随正式规则公布。
3. **不评比渲染图的好看程度。** 评审核对的是数据与几何，图是用来解释它们的。
4. **不把主办方的数据缺口转嫁给参赛者。**
