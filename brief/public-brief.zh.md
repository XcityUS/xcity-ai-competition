## 0. 一句话

**有了真实资料，AI Agent能否自主完成一套有依据、能够核查的城市方案？**

XCITY在同一场地开展两个独立征集。AI赛道检验自主设计、系统推理与数据一致性；机构赛道寻找专业设计团队及后续合作可能。场地位于阿根廷圣胡安省，标称面积1,656 km²。

## 1. 为什么提出这个问题

过去两百年，城市很大程度上围绕化石能源和人类劳动组织：煤与石油驱动机器，人们进入工厂、办公室和商业中心，道路、住宅和基础设施围绕工作与通勤形成。

硅基时代正在形成另一条链：**电力 → 算力 → AI Agent → 机器人**。Agent参与工作、判断与调度，机器人承担更多执行、生产与维护。生产、维护和移动的方式随之改变，城市也需要重新思考工作、通勤与居住的关系。

算力的发展首先受能源条件约束。因此，问题落到一块有阳光、土地，也有真实限制的地方：**当电力、算力、Agent与机器人逐渐成为生产基础设施，城市是否需要重新设计？**

XCITY希望从能源、算力、机器与人的新关系出发推导城市，而不只是向既有城市增加AI功能。

## 2. 场地

**两块相连地块，标称面积1,656 km²。** 场地、两类固定试点、用水、地形、风险、首期独立运行及资料缺口统一见 `brief/site-conditions.en.md`，请先阅读。当前精确几何面积及边界整理版本见 `brief/site-package/areas.json` 和边界变更记录；业主提供的竞赛边界不等于法定地籍确认。

固定试点包括三个农光场和首期生活区，两者都不得重新设计，但用途与状态须分别表达。场地条件必须影响方案的空间结构；不能把这里当成空白画纸，只展示未来的外观。

## 3. 五类城市系统

以下权重是**在规划思考中的侧重，不是互斥用地比例**。五类系统可能复合，并相互依赖。参考位置见 `brief/site-package/zoning/indicative_systems_9_13.json`；它们是主办方参考意向，方案可采纳、调整或推翻，并说明依据，不是确定的供水、供电、审批或用地边界。

| 系统 | 参考权重 | 要讨论的内容 | 参考落位思路 |
|---|---|---|---|
| **能源与算力** | 约60% | 阳光转为电力，再支撑算力，服务场内农业和城市，并向外提供算力服务。取能、冷却、维护和余热去向共同决定位置。 | 较缓、农业价值较低且可处理洪水风险的地方；论证电力、通信、冷却接入，以及与住宅间的噪声、热与维护接口。 |
| **农业生产** | 约30% | 板上发电、板下种植、地面放牧的复合系统；城市如何与固定农光场衔接、生长。开心果、橄榄、葡萄等高大或攀援作物不得进入既定光伏阵列，其外部位置与规模由方案论证。 | 北部、中部平地和河谷，以及与安第斯融雪水系的关系；水源权利、可用量等不能由地理关系直接推定。 |
| **生活与公共生活** | 约5% | 人居城市如何由Agent协调、由机器人参与运行。集聚型聚落支持学校、诊所、商店与街道；庄园型低密生活耗地较快，须明确面积与资源。是一座城市还是多个聚落，由方案论证。 | 日常服务与可靠供水条件附近，处理洪水、重物流和算力设施影响。 |
| **工业与自动化** | 约3% | 农产品加工、制造、光伏与机器人维护、地方生产及场内物流；各阶段须有支撑该阶段运行的生产能力。门户工业与物流门户相联系。无驾驶员货运需要重新安排断面、装卸和人车关系。 | 主地块Pie de Palo山地东侧平坦翼部为门户工业参考位置；可作为后期发展意向，但首期须处理用地及连接条件。 |
| **贸易与国际门户** | 约2% | 货运站、集装箱场、保税及海关仓储等如何与城市相处。门户功能和相应权利、审批应分开说明。 | 主地块东翼约7 km²平地为与门户工业复合的参考意向；联系内陆及大西洋方向，后期建设、首期考虑预留与接入。 |

## 4. 设计到什么程度：一个方案，三个对外尺度

| 尺度 | 范围 | 深度 | 要回答的问题 |
|---|---|---|---|
| **1 · 全场地研究** | 主办方固定竞赛边界全域 | 空间结构 | 五类系统、城镇与中心、交通、资源、容量和分期如何共同成立；从哪里起步、如何增长。不能以自选首期替代全域任务。 |
| **2 · 总体布局与城市设计** | 全部拟建城区及配套设施，涵盖各建设阶段 | 完整方案，分期实施 | 完成各分区布局、容量、设施和系统联系，再安排一、二、三期建设。后续阶段不得留白；城市设计放大区可有多处，不能与首期建设范围混为一谈。 |
| **3 · 重点节点** | 每组一处，共三处 | 详细设计，保留必交视图 | 每处至少一张鸟瞰、一张可见使用情景的人视，以及平面或剖面；说明位置、建设阶段、使用者、运行与上层方案的联系。 |

内部以四层相互衔接的任务检查这三个尺度：**全域结构、完整城市布局、城市设计放大、三个节点**。总体深化区、首期实际建设范围、首批工程和放大区可有重合，但用途与指标口径不同。城市设计放大至少检验一个完整街区或空间单元；不指定隐性最低面积或统一住宅产品。预留地不自动成为建成区、灌溉面积或已兑现需求。

### 节点选择：每组一处（2026年10月26日）

新投稿必须从下列三组各选一处，合计三处：

| 分组 | 可选节点 |
|---|---|
| 生活与公共空间 | A01 未来住宅原型；A02 艺术与文化场所；A03 酷热与Zonda风中的公共空间 |
| 生产与基础设施 | B01 无人机起降与停靠站；B02 物流枢纽与国际门户；B03 算力园区与余热利用 |
| 城市接口与环境 | C01 城市入口与到达序列；C02 农光场与城市边缘；C03 季节性河道公园；C04 与无人驾驶车辆共享的街道 |

允许关联议题合并设计，但每个选定节点都需独立ID及对应证据。G9核对分组覆盖；本次分组不改变既有视图要求。所有方案均须覆盖 A、B、C 三类；不再保留旧编号或十选三例外。

### 十个节点

| ID | 节点 | 要检验的空间问题 |
|---|---|---|
| C01 | 城市入口与到达序列 | 从区域道路进入后的第一段，人、车、货物在哪里分流。 |
| A01 | 未来住宅原型 | 劳动交给机器、通勤不再定义一天时，住宅怎样组织。 |
| B01 | 无人机起降与停靠站 | 起降、充电、分拣、维护与街区、屋顶的关系。 |
| B02 | 物流枢纽与国际门户 | 堆场、口岸与自动分拣怎样与城市共处。 |
| B03 | 算力园区与余热利用 | 模块、共享设施、可信容量与有依据的余热接口。 |
| C02 | 农光场与城市的边缘 | 交织、抬升，或可步行的边界如何成立。 |
| C03 | 季节性河道公园 | 大部分时间干燥，暴雨时承担行洪的空间怎样运行。 |
| A02 | 艺术与文化场所 | 沙漠、山地和暗夜条件如何形成值得到访的公共文化场所。 |
| C04 | 与无人驾驶车辆共享的街道 | 断面、过街与人的安全感如何协调。 |
| A03 | 酷热与Zonda风中的公共空间 | 在地表可能达50 °C的情景下，人仍能使用怎样的户外空间；情景不是每个节点的实测值。 |

**必交视图不要求付费工具。** 仓库脚本可以从自有几何离线生成节点平面、鸟瞰和人视体量图。具备图像工具时按 `AGENTS.md` 制作成品概念图，并登记来源；没有图像工具时保留既有体量图例外、明确标注。图像数量和工具花费不代替详细设计。

## 5. 每个方案都必须回答什么

全文见 `brief/design-requirements.zh.md`／英文对照；机器定义见 `brief/requirements.json`。

| 编号 | 核心要求 | 必须解释 |
|---|---|---|
| M1 | 逐小时无碳能源匹配率（%） | 夜间怎么办；实体供能还是合同匹配。 |
| M2 | 首期IT峰值负荷（MW） | 所采用的电网容量假设。 |
| M3 | 分用途年用水量（m³/yr） | 各项之和与总量一致。 |
| M4 | 冷却WUE（L/kWh）及冷却方式 | 与PUE一起解释水、电权衡。 |
| M5 | 用水短缺30%时先停什么 | 优先顺序及每一步对城市的影响。 |
| M6 | 人机同层交界数量 | 在几何中定位，由脚本核对数量。 |
| M7 | 机器交通规则 | 分离、混行、分时或组合，适用位置与执行方法。 |
| M8 | 公共审计机制 | 谁公布电、水、发电与算力数据，频次及独立核查方式。 |
| M9 | 算力资产控制与接续 | 运营者退出后怎么办。 |
| M10 | 二、三期触发条件 | 可观察条件，不是日期表。 |
| M11 | 不可逆决策 | 至少三个首期以后难以改变的决定及理由。 |
| M12 | 首期岗位、居民与住宅相互核对 | 人数远多于岗位时，其他人是谁、依靠什么生活。 |

没有数字依据的形容词、没有基线的减量、没有接收者的余热利用、没有优先次序的缺水应对，以及没有技能构成和培训安排的就业数字，都不足以回答相应要求。

## 6. 八项Agent任务

`brief/agent_taskbook.json`：场所身份、能源与算力、干旱地区的水、人和机器、功能与生产、全域城市形态、数据与AI治理、三阶段实施。每项通过 `compliance_matrix.json` 指向 `proposal.md` 实际回答它的章节。保留原十四个机器关联章节，不新增一套互相冲突的正文编号。

## 7. 提交什么

每份投稿位于 `submissions/<你的GitHub账号>/<方案slug>/`，以GitHub拉取请求提交。完整格式见 `docs/submission-guide.md`。

| 成果 | 内容 |
|---|---|
| 设计说明 | `proposal.md`，十四个编号章节；以 `templates/proposal.template.md` 为起点，形成完整设计论证，不设最低1500词门槛。 |
| 结构化数据 | `manifest.json`、`metrics.json`、`compliance_matrix.json`、`assumptions.json`、`sources.json`；新投稿使用当前设计深度矩阵。 |
| 几何 | `geometry/`中的全域结构、总体深化区、用地、建筑、交通、分期和三个节点。必要场外联系可用可选 `context/` 研究层，须标明状态、不进入场内开发统计、不表示已取得建设权。 |
| 图纸 | 保留脚本要求的独立核对图及共享节点定位图；默认输出只是基础工具，正式空间图纸仍需检查和编辑。 |
| 节点视图 | 每节点保留平面或剖面、鸟瞰、人视要求及稳定ID。 |
| 正式图册 | 主册 `drawings/a3-booklet.pdf`、独立技术附件 `drawings/a3-technical-appendix.pdf`、页码索引 `drawings/presentation-index.json` 和A0展板，按适用版本提交。 |
| 网页 | `report/proposal.html`，可离线阅读。 |
| 自检 | `self_check.json`，公开PR前通过适用的十二项自动检查；不代表设计评审通过。 |

新建矩阵使用 **`schema_version: 2`**，按 `brief/design-depth.json`、`schema/design_depth_matrix.schema.json` 与模板执行。逐层及逐节点写明 `decision`（具体空间判断）、`scope.extent`／`scope.phase`（范围与阶段或情景）、图纸／几何／指标／正文章节、状态及缺口。`gaps[].kind` 区分主办资料缺失 `organiser_data`、专业核实 `professional_verification`、参赛设计未完 `entrant_design`。新版必须有实际空间证据，不能用资料缺口替代必交图纸与几何。`documented`表示已提供，`partial`表示尚有缺口，都不是内容已充分。

仅两个主办方列明的历史目录可继续读取旧v1矩阵并提示下一次修订迁移到v2；新目录必须使用v2，不得自填旧版本绕过。不能只改版本号，须补齐真实判断、范围与缺口类别并核对引用。两个主办方列明的既有投稿不被批量重写；节点、图册和矩阵例外分别适用。详见文末兼容说明及 `docs/design-depth-guide.md`。

高质量图像、短视频、动画、3D及交互页面可以帮助说明空间、一天的使用及人机协作，但额外媒介不加门槛。成品概念图是解释层，不是实测、官方边界、居民意见或审批证据。按 `image_provenance.json` 记录工具、模型、完整提示、日期、后期及参考图权利；图像须与提交几何一致，不能用装饰性画面替代设计。

## 8. 怎样评审

**先自动合规，再独立内容评审。** 十二项检查覆盖文件、路径、已编码的几何与数值核对、离线文件、任务回应与引用、自主性披露、边界、图纸版本、取舍及深度矩阵／图册包装。G4现行数字核对容差为2%，它不是地籍、施工或一切资料的统一精度标准。自动检查不判断空间品质、适建性、图纸可读性或工程可行性。

| 评审主项 | 通过什么观察 |
|---|---|
| 自主性 | 自主性分类与披露；在同类内比较。 |
| 推理质量 | D1、D2、D4、D5、D6、D7的依据、关系与取舍。 |
| 可核查性 | 数字、几何、来源、版本和自动检查的可复核程度。 |
| 原创性 | D3，结合全体投稿比较。 |

| 维度 | 要问的问题 |
|---|---|
| D1 场地及任务相关性 | 换一块地，方案会不会不同？ |
| D2 能源、算力与水的推理 | 用哪些量建立平衡，是否理解并接受代价？ |
| D3 原创性与AI城市创新 | 相对其他方案有什么独立贡献，而非共同套用的答案？ |
| D4 可行性与分期 | 首期建成后再无后续，是否仍是可生活和生产的地方？ |
| D5 公共利益与包容 | 排除了谁，是否理解这一点？ |
| D6 风险、合规与数据治理 | 哪种失效在这里实际可能发生，谁来决定应对？ |
| D7 已声明的取舍 | 不优化什么、为什么、后果及由谁承担？ |

权重随正式规则公布，方案按 `autonomous`、`human_supervised`、`human_directed` 各类分别比较。**主办方未提供的数据本身不导致扣分或淘汰**；参赛者仍须诚实说明采用的假设／情景、局限与后续核实。参赛者漏交必需设计、引用或数字，与主办资料缺口不同。

v2的建筑面积、覆盖率和容积率按建筑与 `master_area` 相交部分计算，区外建筑面积另报；这些不是自动得到的实际首期量，首期建设阶段和范围仍须另行核对。仅两个历史目录的v1保留原全包建筑分子以便复现。

报告分开显示：自动结果、内容 `not_assessed`、待深化事项。自动全部通过不等于方案完整、工程可行或已获批准。

## 9. 两个征集，同一场地

两赛道共用场地和条件，各有任务、交付及评审，不能把机构要求直接套给Agent。

| 内容 | AI城市开放征集 | 设计机构征集 |
|---|---|---|
| 目的 | 检验自主设计、系统推理与数据一致性。 | 获得城市设计并寻找专业团队。 |
| 参加方式 | 公开参加，如实披露Agent、模型与人工介入。 | 机构资格、相关业绩及实际团队。 |
| 设计重点 | 全域系统、首期、资源平衡与运行；同时有空间证据。 | 全域结构、完整城区、街道街区与公共空间品质。 |
| 交付 | 仓库中的方案、几何、指标、来源及自检。 | 按机构任务书提供图纸、说明、测算与可编辑成果。 |
| 评审 | 自主性、推理、可核查性与原创性。 | 场地回应、空间品质、专业完整性与实施判断。 |
| 后续 | 公开能力与贡献记录。 | 后续合作须按另行约定，不因获奖自动取得委托。 |

机构最新流程只以 `brief/firm-track.en.md` 和[机构官网](https://xcityus.github.io/xcity-ai-competition/practice.html?lang=zh)为准；此处不展开机构报名和材料操作。

## 10. 遴选之后

承诺状态以 `brief/awards.json` 为准，不能把待公布项目写成已经发放。

- 经审核公布的方案携带提交目录sha256，可核对展示版本与评审版本。
- 合并后评审团队以独立PR加入 `FEEDBACK.md`，记录书面理由。

## 洪水资料：筛选与已核实限制

- **季节沟道**：`water/channels_dem.geojson`为DEM推导线，不是实测河岸。真实沟道不得永久建设；脚本的示意缓冲用于提示核查，不是法定退界，小沟道也未完整清查。
- **洪泛敏感筛选**：`water/flood_sensitive_dem.geojson`使用60 m DEM，以距推导沟道1.5 km内且HAND低于3 m等方法筛选，约503 km²。它不是湖泊、实测设计洪水线、法定分区或永久禁建全域；筛选外也不自动安全。
- **已核实限制缺口**：未提供实测设计洪水边界、设计流量／重现期或已核实退让线。说明假设、避让、过流与防护及所需水力／现场验证；不能伪造安全结论。仅落入筛选区本身不自动判失败。

## 必需的展示结构

主册阅读骨架为全域图 → 共享定位图 → 三个有标题与位置的节点 → 分期 → 关键指标。把场地分析、容量与系统关系、完整首期及城市设计放大放到相应位置，不能压成固定六页摘要。**有解释作用的正式diagram、平面、必要剖立面、体量、流线、服务与运行图必须留在主册**；原始模型截图、重复控图、完整计算和程序日志放技术附件。图册可合图、可自由排版，图纸范围、阶段、标题、来源状态和必要尺度须清楚。机器只核查适用的包装／页码引用，不替人判断设计。

## 设计工作流程、深度与评审（与当前机器版本对应）

读取并核对版本 → 分析场地与限制 → 比较重要空间选择并说明取舍 → 确定全域结构 → 落实首期及城市设计放大 → 深化三节点 → 复算指标 → 组织正式展示 → 自动检查与内容自审 → 修订提交。不为比较制造无价值备选，也不因脚本生成默认图册便宣告完成。

沿用 `brief/design-depth.json` 和矩阵schema的版本管理：新目录必须使用v2；仅两个列明历史目录的旧v1保留兼容读取并提示迁移，不能靠自填旧版本取得例外；既有投稿记录不被重写。所有方案的节点选择统一执行 A、B、C 三类各一处，不设历史节点例外；图册索引升级与矩阵升级的兼容规则分别适用。资料版本变动时，识别受影响的几何、指标、图纸和结论并重算／重绘；保留既有评审记录。

### 各层范围独立，节点可分散

全场地总体规划必须覆盖全部已发布场地。须区分①全域规划、②首期实际建设及配套设施、③城市设计放大区、④各深化节点、⑤渲染取景框；这些边界不能互相替代。放大区可以仅覆盖部分节点，也可以不包含所选三个节点。三个节点不必相邻、不必位于同一城区、不必全部位于master_area.geojson内，也不必全部首期建设；逐一说明位置、阶段、使用者及全域作用。首期完整指生活和生产体系能够独立运行，可由空间分离的城区和设施组成，但须证明交通、电、水、通信等必要联系。片区用地、容积率和建筑量与片区外设施分别统计。不得为了拼齐节点而强迫算力园区紧邻住宅或余热用户；选址、缓冲、冷却和真实余热网络须有依据。渲染视角用于解释方案，不定义设计范围。

C01明确包含**主入口与到达序列**。不选C01也须在全域规划中交代主要接入、区域联系和人货分流；选择C01才须深化入口节点。十个节点是三类深化选题，不代表未选议题可以从总体规划中省略。A01/B03/C02只是合法组合之一，不是必选组合或邻接范式。分散节点用全域定位图和独立放大图表达，统一编号，不遗漏远端节点，也不虚构直接连接。

### A0建设分期图与数据表

A0展板须包含清晰标注的一、二、三期分区图及对应的数据表，覆盖各开发分区与分散的生产、基础设施，固定试点另行区分。各分区、各阶段须列出本期新增和累计人口、住房、岗位，阶段目标、工程与公服市政配套、预计工期或相对年份、建设顺序和前置依赖，以及可观察的启动与扩展条件。居民、就业及访客不能混算，新增不能冒充累计，预测不能冒充确定条件；有依据的规模区间可以使用。只有三色分区而无建设计划不算完成。工期是受资源权利、勘测、审批和需求约束的情景，不得编造已批准日历。阶段合计须与分区、metrics.json（含首期人口）一致；分区编号、空间范围和阶段须对应geometry/phasing.geojson；同阶段的分散设施不要求相邻。

提交phasing_programme.json，使用仓库模板并关联分期图与A0展板。自动检查只验证结构、数字对账、文件和阶段编号；可实施性及可读性由评审判断。


### 完整城市范围——2026-10-27澄清

设计对象是完整城市，不只是一期。须完成全部拟建分区、各期容量、中心与居住、生产和算力、公服、交通、市政及系统联系的整体布局，再安排建设分期。二、三期不得留白：须给出空间布局、人口岗位、阶段目标、建设顺序和前置条件。首期能独立运行是实施检验，不是设计范围上限。城市设计放大区可有多处，不要求包含三个节点。设计深度表第二层改为overall_layout；M1—M12仍按各自注明的首期运行口径计算，全期人口、岗位与建设顺序在分期表中另行对账。


## 城市级专题图与整体空间表达

先把功能安排和城市结构想清楚，再通过专题图检查系统关系，落实城市设计与三个节点，并用同一套完整布局制作整体轴测或大鸟瞰。图中发现矛盾，就返回调整设计。相邻或分散都必须有理由；不能为了分而分，也不能为了把三个节点放进一个画面而排城市。

主图册须回答以下六类问题。可合图、合页，六个主题不等于六页。各图采用同一套城市几何、分区名称、方向与可比比例尺；需要放大时清楚标注范围。保留全场地定位图，城市级研究不能缩小主办方给定的总体规划范围；全场地结构也不必与城市设计放大区具有相同的逐栋建筑细度。

| 主题 | 必须讲清楚 | 图中应有的内容 |
|---|---|---|
| 规划结构 | 城市怎样组织、各区怎样形成整体 | 中心层级、分区角色与规模、主轴、边缘和地区联系。 |
| 功能布局 | 各种城市活动放在哪里、怎样配合 | 居住、公服商业、算力生产、农业物流的位置、混合及相邻／分离理由、运行联系。 |
| 道路与交通 | 怎样进入、通行与服务城市 | 主入口、连续路网与层级、公共交通、步行骑行、货运服务、关键交叉接口；场外接入标注权利状态。 |
| 生态与景观 | 地形、水与开放空间怎样形成连续格局 | 季节沟道、保护与开放空间、景观联系、种植遮阴及水资源依据；不得虚构湖泊、成活绿化或实测洪水边界。 |
| 土地利用 | 土地按什么单元安排、面积容量怎样对应 | 适当细度的街块／用地单元、类别与图例、混合口径、面积和容量，避免重复统计。 |
| 公共空间与公共服务 | 人在哪里活动并获得服务 | 公共中心、学校医疗市场等设施与公共空间、步行联系、服务层级、容量及覆盖假设。 |

每张图说明它检验哪个决定、发现什么问题。功能布局解释活动与运行关系，土地利用表达空间单元及面积容量；合图时两者仍须读得明白。把同一底图换六次颜色不算完成。细度服务于问题，不要求把全场地每栋建筑或每宗地都画满。参考图用于说明表达方法，不是照搬其他城市的河湖、绿化、路网、密度或造型。

整体轴测／大鸟瞰须表达完整城市或聚落体系的分区、中心、主要路网、体量高度特征、景观和生产背景，并标明实际范围、投影／相机、阶段或远期情景与简化内容。轴测可以是清楚的示意体量表达；成品透视须与对应几何控制图一致。远处分区无法在一个真实镜头里读清时，可用整体轴测及一致的局部放大，不虚构镜头或把分离地区拼成连续城区。画面不必包含全部三个节点。局部鸟瞰不能代替整体视图，整体效果图也不能代替专题图。

分期图及人口、住房、岗位、公服市政、建设顺序与依赖表使用同一套分区编号和布局。三个深化节点用于检验城市决定，不决定城市边界。AI Agent图册不设固定页数；以清楚说明完整方案为准，更多页数、图像或细节本身不加分。

在现有深度矩阵的 `overall_layout` 行关联这些图纸、几何、指标和正文章节，不另加一套申请表。自动检查只能核对文件与版本等已编码关系；六类专题是否有用、整体图是否忠实仍属设计内容评审，不能自动判通过。


方法与复核依据见 [城市设计方法说明](https://github.com/XcityUS/xcity-ai-competition/blob/main/docs/city-design-method-basis.md)。区分地区边界／编号、功能分区、土地利用单元和建设分期，并用同一套几何及统计说明关系。城市级先画清主次路网及地区／街块结构，局部放大再深化。只有渲染而缺少必需专题图与规划平面，不算完成。
